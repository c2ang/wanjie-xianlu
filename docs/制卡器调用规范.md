# 万界仙录 · 制卡器调用规范

> 版本：`xianlu/1.2.0`　适用于：万界仙录插件 1.2.0　配套契约文件：`schemas/*.json`
> 读者：要接这个资料包的制卡器 / 生成脚本 / 别的 AI 应用。
> 一句话：**插件给的是「背景骨架」不是人物**——它随机抽出一份门派、身份、境界、灵根、主修功法；姓名、性格、经历、台词由写卡的模型补完。制卡器要做的事只有两件：按规定调接口取背景，拿到背景后再开始写卡。

---

## 0. 一页速览

```
制卡器 ──① xianlu_generate(category, count=1..10, filters, seed)──▶ 背景骨架（门派/身份/境界/灵根/功法）
        ──② xianlu_lookup(id, detail_level=complete)──────────▶ 单条完整字段 + 原文摘录
        ──③ xianlu_related(id)────────────────────────────────▶ 关联（法宝本体/宗门/同类）

拿到 ① 的 background.fields，就可以开始写卡了：姓名、性格、经历由模型补。
```

- **数量不固定没问题**：`count` 是 1–10，多类别就多发几次（每个类别一次），或离线用组合模式一次取完。
- **可复现**：`seed` 相同 + 资料包相同 = ID 序列相同。做「试抽 / 换一批 / 复现某张卡」都靠它。
- **三档详细程度**：`compact`（约 250 字，够挑人）/ `standard`（约 800 字，够写卡）/ `complete`（约 1900 字，含原文摘录）。
- **不要伪造女性身份**：素材的 `gender_basis` 为空表示「资料没说」，此时你可以按需补全，但**必须**在卡里或生成说明中标注为补全。

## 0.5 插件给的是什么（定位，先看这段）

**不是人物，是门面资料。** 一条结果 = 一份可以直接开写的背景骨架：

| 类别 | `background.fields` 里有什么 | 由模型补什么（`to_be_authored`） |
| --- | --- | --- |
| `female_cultivator` 女性修仙者 | 身份、所属门派、境界、灵根、主修功法、气质外形 | 姓名、性格、个人经历、说话方式、门派内具体职务、功法招式细节 |
| `female_deity` 女性神佛 | 尊号、神职、道场、果位/神阶、信众与香火 | 具体化身形象、灵验传闻 |
| `female_artifact_spirit` 女性器灵 | 依附法宝、法宝类别、品阶、显化形态、能力与限制 | 器灵姓名、女子形态与样貌、性格、认主经过 |
| `female_beast` 女性异兽 | 物种、血脉、品阶、栖息地、天赋神通、化形条件 | 化形后的女子形象、名字、性格 |

`background` 对象长这样（女修，seed=42）：

```json
{
  "fields": {
    "身份": "大宗门圣女、仙门传人",
    "所属门派": "青云宗（宗门）",
    "境界": "元婴",
    "灵根": "火灵根",
    "主修功法": "裂天拳",
    "气质外形": "清冷出尘、高不可攀"
  },
  "provenance": { "所属门派": ["doc_fd16bda643a0bb09"], "境界": "library" },
  "created_by": "资料库随机配对（seed 可复现）",
  "to_be_authored": ["姓名", "年龄段与生日", "性格", "个人经历", "说话方式", "门派内的具体职务", "功法的招式细节"],
  "pools_ready": true,
  "note": "门派/境界/灵根/功法为资料库随机配对（各自有原文出处），角色本身由模型创作。"
}
```

三条使用规则：

1. **`fields` 里的值是「设定」，不是「这个人的描述」**——写卡时把它们当世界观约束来用（她属于青云宗、元婴期、火灵根、练裂天拳），不要当成人物的自述。
2. **`to_be_authored` 里的东西必须由你（模型）写**，而且这是卡的主要工作量：名字、性格、来路、说话方式。
3. **`provenance` 是给「可追溯」用的，不是给人读的**：`entity` 表示取自素材本身，`library` 表示从资料库随机配对，数组是原文 `source_ids`。写卡时不必引用这些 ID。

如果 `pools_ready` 为 `false`，说明资料包没导入池子（旧版本导入过）——此时只有 `境界` 能随机，门派/功法缺失。让用户重跑一次「导入内置资料包」即可。

## 1. 四种接入方式（按你的运行环境选一个）

| 方式 | 适用 | 调用形态 | 优点 | 限制 |
| --- | --- | --- | --- | --- |
| **A. Function Tool** | 制卡逻辑就在酒馆内（提示词 / 角色卡 / Quick Reply） | 模型直接调 5 个工具 | 最完整、有筛选与去重 | 需要模型支持 tool calling |
| **B. 斜杠命令** | 同酒馆、但模型不会调工具 | `/xianlu action=generate category=… count=3` | 任何模型都能用 | 只能传字符串参数，filters 有限 |
| **C. 离线 CLI** | 制卡器是独立程序 / 批量出卡 | `python tools/pick_random.py --category … --count 3` | 无需酒馆，输出 JSON | 需本机有 Python 3.8+ |
| **D. 静态兜底** | 只想要「模型偶尔想起设定」 | 导入 `世界书-万界仙录-素材.json` | 零集成 | 无检索、无随机、占上下文 |

A/B/C 三者读同一份资料包，**抽取算法逐字节一致**（由 `tools/verify_cli_parity.mjs` 守护），所以「酒馆里试抽 3 个，离线再复现」是能对上的：参数与 `seed` 一样，结果就一样。

## 3. 工具与参数

### 3.1 `xianlu_generate` — 随机抽素材（主力）

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `category` | enum | ✅ | — | `female_cultivator` 女性修仙者 / `female_deity` 女性神佛 / `female_artifact_spirit` 女性器灵 / `female_beast` 女性异兽 |
| `count` | int 1–10 | | 1 | 一次抽几条；超过 10 会被截到 10 |
| `filters.realm` | string | | — | 精确境界，如 `金丹`、`元婴`；写 `元婴期` 也能识别（含「期」不影响） |
| `filters.realm_min` / `realm_max` | string | | — | 区间；按 19 级境界排序比较 |
| `filters.race` / `bloodline` / `grade` / `artifact_type` / `species` / `habitat` / `sect` / `domain` | string | | — | 字段**包含**匹配（宽松） |
| `filters.can_transform` | bool | | false | 只取「有化形条件」的异兽 |
| `filters.tags` | string[] | | — | 偏好标签，**不淘汰**，只加权 |
| `filters.keyword` | string | | — | 同样只加权 |
| `random_mode` | enum | | `weighted` | `weighted`=标签/关键词匹配度高者更易被抽到；`uniform`=纯随机 |
| `seed` | int/string | | 随机 | 相同 seed + 相同资料包 = 相同 ID 序列 |
| `exclude_recent` | bool | | true | 排除最近抽过的 N 条（`recentWindow` 默认 20） |
| `detail_level` | enum | | `standard` | `compact` / `standard` / `complete` |

**硬性 vs 软性**：`filters` 里除 `tags`、`keyword` 外全部是**硬条件**（不满足直接不进候选池）；`tags`/`keyword` 只影响权重。

**候选不足时的行为**（会写进 `warnings`，请转述给用户）：
1. 先放宽「近期去重」（把最近抽过的重新放回池子）；
2. 还不够，且未允许待核查 → 本次临时纳入 `pending`（原文依据不足）素材并提示；
3. 仍然为 0 → `success:false`，`results:[]`，`warnings` 说明原因。

### 3.2 `xianlu_search` — 按条件找（不用随机）

| 参数 | 说明 |
| --- | --- |
| `scope` | `entity`（默认，查四类素材）/ `document`（查资料库原文，如「器灵怎么诞生」「金丹期特征」）/ `auto`（实体不足时自动附带原文片段） |
| `category` / `keyword` / `tags[]` / `realm` / `limit`(1–20) / `allow_pending` / `detail_level` | `category` + `keyword` 是主流组合；`scope=document` 时 `keyword` 必填 |

`scope=document`/`auto` 时 payload 里会多一个 `documents` 数组（`title`/`category`/`source_path`/`snippet`），这是资料库原文片段，**不是实体**。

### 3.3 `xianlu_lookup` — 按 ID 或名字取单条

`id` 或 `name`（二选一），`detail_level`。用于「抽到 ID 后补全字段」，比再抽一次便宜。

### 3.4 `xianlu_related` — 取关联

`id` 或 `name`，可选 `relation_type`（如 `spirit_of_artifact`）。器灵→法宝本体的关联通常指向**库外对象**，会在 `meta.notes` 里以「外部关联：盘古幡（spirit_of_artifact）」形式给出。

### 3.5 `xianlu_save_result` — 收藏

`entity_id`（或 `name`）+ `note`。只写进插件收藏区，**不碰人物卡**。

字段含义：

| 字段 | 怎么用 |
| --- | --- |
| `id` | 后续 `lookup` / `related` / `save` 的键；也可作为制卡器的「素材指纹」写进卡 |
| `quality` / `quality_label` | `verified` 原文可证 / `inferred` 合理推导 / `adapted` 原创改编 / `pending` 待核查 / `conflict` 冲突 |
| `adaptation_flag` | `true` 时**不能**说成「资料原文」 |
| `gender_basis` | 女性身份依据；**空字符串 = 资料没写**，你可以补，但要注明补全 |
| `facts` | 中文标签→值的有序表；键名集合见 `xianlu-enums.json` 的 `categories.*.fields` |
| `material_note` | 器灵惯例：只给法宝名与形制，女性化由模型完成 |
| `content` | 仅 `complete` 返回，原文摘录（≤800 字） |
| `warnings` | **必须**转述；里面是「候选不足/已放宽/含待核查」这类诚实提示 |

三档详细程度的预算（`facts` 键数与单值长度的上限）：

| detail_level | 总预算 | facts 键数 | 单值 | 适用 |
| --- | --- | --- | --- | --- |
| `compact` | 900 字 | 4 | 90 字 | 批量挑人、列表预览 |
| `standard` | 3200 字 | 10 | 160 字 | 直接写卡 |
| `complete` | 7600 字 | 全部 | 400 字 | 精修、需要原文措辞 |

## 5. 抽样语义（要写进你的重试/复现逻辑）

- **可复现**：`seed` 相同 + 资料包版本相同 → 结果相同；换了资料包（版本号变了）就不保证。
- **weighted**：权重 = 1.0 基础 + 关键词命中名字 3.0 / 命中全文 1.5 + 每个标签命中 2.0（全文命中 1.0）+ `verified` 0.6 / `inferred` 0.3 + 标签数量微调。想「纯随机」就传 `uniform`。
- **不放回**：同一次调用内不重复；跨调用靠 `exclude_recent` 去重，去重窗口默认最近 20 条。
- **候选少**：`count` 大于候选数时返回实际条数，并在 `warnings` 里说明「只有 N 条」。

## 6. 制卡器推荐流程

```text
1) 定调：用户要什么（类别 / 气质 / 境界区间 / 要不要可化形 / 要几个）
2) 取背景（核心一步）：对每个类别各调一次 generate
     → 结果里的 background.fields 就是「门派 / 身份 / 境界 / 灵根 / 主修功法」
     → 这一步拿到的已经是能开写的资料，不需要再问模型「她是谁」
3) 要更细：对选中的 id 调 lookup(detail_level=complete)，拿原文摘录与完整字段
4) 要关系：调 related，拿宗门 / 法宝本体 / 血脉同类，用来撑场面
5) 写卡：模型按 background.to_be_authored 补 名字 / 性格 / 经历 / 台词
6) 记账：把 id + seed 写进 creator_notes，下次可复现
```

**制卡器侧的接口建议**（把它写进制卡器的人物卡模板里，模型就会照做）：

```python
def fetch_background(category, count=1, filters=None, seed=None):
    """只取背景骨架，不取人物。返回的每条都能直接开写。"""
    payload = call_tool("xianlu_generate", {
        "category": category, "count": count,
        "filters": filters or {}, "seed": seed,
        "detail_level": "standard",
    })
    out = []
    for r in payload["results"]:
        bg = r.get("background") or {}
        out.append({
            "id": r["id"],
            "fields": bg.get("fields", {}),        # 门派/身份/境界/灵根/功法
            "to_be_authored": bg.get("to_be_authored", []),
            "note": bg.get("note", ""),
            "quality": r["quality"],
        })
    return out
```

伪代码（多类别、数量不固定）：

```python
def 做一张卡(题材, seed):
    主角 = fetch_background("female_cultivator", 1, {"tags": 题材["气质"]}, seed)[0]
    器灵 = fetch_background("female_artifact_spirit", 2, {}, seed + 1)
    异兽 = fetch_background("female_beast", 1, {"can_transform": True}, seed + 2)

    卡 = {}
    卡["name"] = 起名(题材)                                   # 模型写
    卡["description"] = 把背景写成叙事(主角["fields"])          # 门派/境界/灵根/功法
    卡["personality"] = 写性格(主角)                            # 模型写，背景里没有
    卡["first_mes"] = 写开场(主角["fields"])                    # 用门派/境界做场景
    卡["creator_notes"] = {"seed": seed, "ids": [...], "素材版本": "万界仙录 1.2.0"}
    return 卡
```

> **数量不固定**：`category` 是单值，所以「1 女修 + 2 器灵 + 0~1 异兽」就是 3 次调用；
> 离线批处理可用 `python tools/pick_random.py --combo female_cultivator:1,female_artifact_spirit:2`。

## 7. 背景骨架 → 角色卡的映射

| 卡片字段 | 主要来源 | 怎么用 | 注意 |
| --- | --- | --- | --- |
| `name` | —（`to_be_authored`） | 模型起名；可参考「名字生成」原文 | 模板名如「圣女型」不能当人名 |
| `description` | `background.fields`：身份 / 所属门派 / 境界 / 灵根 / 主修功法 | 写成叙事：「青云宗圣女，元婴期，火灵根，主修裂天拳」 | 别直接贴 `键：值` |
| `personality` | —（`to_be_authored`） | 模型自己写，可参考 `facts.性格` 作气质基调 | 模板语要具体化 |
| `first_mes` | `background.fields` + `facts.外貌` | 用门派/境界/法宝本体做场景 | 器灵用 `material_note` 的口径 |
| `scenario` | `background.fields.所属门派` / `道场` / `栖息地` | 场景锚定在素材给的势力里 | 不要自创一个更强的宗门 |
| `mes_example` | `to_be_authored` 的台词 + `related` 的人 | 对话由模型写，关系与素材一致 | — |
| `creator_notes` | `id` / `seed` / `quality` / `provenance` | 溯源与复现 | `adapted` 必须注明改编 |

**三条硬规矩**
1. `background.fields` 是**设定约束**（她属于哪、什么境界、练什么），不是人物自述；写进卡里时保持与资料一致，别改门派、别抬境界。
2. `to_be_authored` 里的一切（姓名、性格、经历、台词）都是**创作**，不得说成「资料库原文」。
3. `quality=adapted` / `adaptation_flag=true` → `creator_notes` 注明「素材含原创改编」；器灵的女子形态一律是补全。

## 8. 错误与降级

| 现象 | 含义 | 该怎么做 |
| --- | --- | --- |
| `success:false, results:[]` | 没有候选 | 读 `warnings`；放宽境界/去掉 `can_transform`/允许 `pending` 后重试一次，仍失败就告知用户 |
| `warnings` 含「候选不足」 | 返回条数少于 `count` | 按实际条数用，不要重试刷数据 |
| `warnings` 含「已包含待核查」 | 本次含 `pending` | 卡里标注「资料依据不足」 |
| 模型调不到工具 | 该模型不支持 tool calling | 降级到方式 B（斜杠命令）或 C（离线 CLI） |
| 资料库为空 / `stats` 为 0 | 没导入资料包 | 先 `importBuiltinPack` 或面板导入；否则只能使用方式 D |

## 9. 制卡器自测清单

1. `generate(count=3)` 返回 3 条且都有 `id`。
2. 同 `seed` 连调两次，ID 序列相同。
3. `generate(filters={"can_transform":true})` 的异兽都有非空 `human_form_condition`。
4. `lookup(id, "complete")` 的字段数 ≥ `standard` 的字段数。
5. `related(id)` 对器灵能给出「外部关联：法宝名」。
6. `quality` 与 `adaptation_flag` 的组合在卡里被如实标注。
7. `warnings` 非空时，生成的卡/日志里能看到转述。
8. 离线 CLI：`python tools/pick_random.py --category female_cultivator --count 3 --seed 42` 与酒馆内同参抽到的 ID 一致。
9. 结果里 `background.fields` 至少有「身份 / 所属门派 / 境界 / 灵根 / 主修功法」四项（女修），且 `pools_ready` 为 true。
10. 写卡时**没有**把 `to_be_authored` 的内容（姓名/性格/经历）当成资料库事实。
